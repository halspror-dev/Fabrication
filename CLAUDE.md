# Fabrication

- Finding your way around: if graphify-out/graph.json exists, run graphify query "<question>" to see how the code connects before you grep. Refresh it with graphify update . after big changes.
- Cross-project notes: `.claude/skills/project-notes`. Read your inbox in `halspror-dev/project-notes` when a thread starts and update your status file before it ends.
- Web research: `.claude/skills/research`. Fetch with its tool, read grep matches not whole pages, and only report what a saved page shows.
- Design changes: every moving part gets an OPEN and CLOSED (or rest and full-travel) state, drawn and checked for clearances (`python3 drawing-scripts/templates.py` prints the checks), so the mechanism is proven before anything is cut. No 2D drawing pages or 1:1 templates (carlie, 2026-10-26): parts are printed and cuts ordered from the DXFs.
- Checking a build: run `check3d.py` (short summary) and `pagediff.py`; send only the changed pages to the `render-reviewer` subagent (`.claude/agents/render-reviewer.md`); don't open render PNGs or the PDF in the main thread. Full visual pass on all render pages (by the subagent) once before a version goes to carlie or out for an order. A PreToolUse hook (`.claude/hooks/check3d-before-push.sh`) runs `check3d.py` before every `git push` and blocks the push if it fails; fix the clash, don't bypass the hook.
- One design version per thread: read `drawing-scripts/STATE.md` first; update it and commit before ending. Start a fresh thread after two failed fixes of the same problem.
- Long work and big prompts: one phase per thread (catch-up/research/design, then act, then report), each starting from the committed `drawing-scripts/STATE.md`. Past ~100k context, update `drawing-scripts/STATE.md` and continue in a fresh thread. Don't keep a thread awake to watch a long run: have the run write a short summary file and check it with a few spaced `send_later` checks, each in a fresh thread that reads only `drawing-scripts/STATE.md` and the summaries. Start deep dives right after the weekly usage reset (Sat 5 AM), after checking weekly %.
